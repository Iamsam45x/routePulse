# RoutePulse

Campus transportation optimization system for Berry College: a prediction engine
that forecasts passenger demand and travel times, a constraint-aware optimizer,
and a discrete-event simulator, surfaced through a React operator dashboard.

> The authoritative game plan lives in **`Wild Bugs.md`** (system architecture,
> data models, algorithms, API contracts, evaluation protocol, and priorities).

## Current scope

This repo currently implements the **prediction engine** (our team's workstream),
plus the shared schemas and dummy inputs. The optimizer, validator, simulator,
API, and evaluation modules are stubbed for the other workstreams.

## Prediction engine (our part)

`backend/app/prediction/`:

| File | Responsibility |
|------|----------------|
| `features.py`   | time buckets, day type, class-change features |
| `eta.py`        | travel-time / ETA estimation (EWMA + schedule fallback) |
| `demand.py`     | passenger demand forecasting (historical-mean baseline) |
| `risk.py`       | overload / crowding risk (demand vs capacity) |
| `predictor.py`  | unified entry point + output contract |
| `explainer.py`  | optional Groq (GPT OSS 20B) explanation layer |

All numerical predictions are computed in Python — **deterministic and
explainable, no LLM tokens in the core path**. The LLM is used only to explain
results and is optional (see `.env.example`).

## Quickstart

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   (or use the interpreter directly)

pip install pydantic pytest        # minimum for the prediction engine

python scripts/import_synthetic_data.py  # map routepulse_synthetic_data.json -> data/
python demo_prediction.py                # run a forecast cycle
python -m pytest -q                      # run tests
```

## Dummy inputs

The canonical dummy dataset is `routepulse_synthetic_data.json` (generated by
`generate_routepulse_data.py`): **40 stops, 10 routes, 25 vehicles, 200 trips,
900 demand records, 1100 ETA samples, 4400 GPS traces, and 5 scenarios**.

`backend/scripts/import_synthetic_data.py` maps it into the shared Pydantic
schema and writes the files under `data/`. Teammates can swap in real campus
data by producing the same schema — the engine does not change.
